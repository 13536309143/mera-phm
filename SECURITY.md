# Credential and data handling

Keep real API configuration in an ignored `.env` file or environment variables. `.env.example` contains placeholders. The local dashboard binds to `127.0.0.1`; it is not a production authentication or authorization service.

Agents have a fixed tool allowlist. They cannot execute shell commands, read arbitrary files, access model targets for the current query, or control physical equipment. These boundaries do not prove that natural-language explanations are factually correct. Canonical predictions and intervals come from supervised tools; original LLM prose is marked as semantically unverified.

Provider errors are summarized without echoing their original exception text. Every API run has request and completion-token limits. Completion limits exclude prompt tokens and are not monetary caps. The opt-in experiment harness logs measured provider usage and uses a conservative admission estimate for its separate aggregate budget.

If a credential is committed, remove it from public history and revoke it with its provider; deleting the latest file alone is insufficient. Report repository issues without including the credential, customer data, or raw private logs. No dedicated private vulnerability-reporting channel is currently established.
